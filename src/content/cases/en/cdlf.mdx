## Context

For CDLF (Clínica de la Familia) I built three products on a shared base:

- **Contact center:** AI-assisted messaging over Messenger and Instagram, with a knowledge base and handoff to staff.
- **Suite:** the internal web app, with users, roles, sessions, auditing, metrics, a knowledge base and manageable open questions.
- **doctors-ai:** a shared patient memory for the medical directors, sourced from Google Drive, with interchangeable AI providers (OpenAI or Gemini), with a patient monitor in the Suite (timeline, lab charts, vital signs and alerts). The monitor was designed and tested with synthetic data.

Each product has two variants: `local/`, on Docker Compose, and `aws/`, the SAM template it runs on in production.

## Contact center architecture (AWS variant)

```text
Meta (webhook)
  → intake Lambda: verifies HMAC signature; 200 only once SQS confirmed
  → SQS FIFO grouped by patient
  → worker: receipts and idempotency in Aurora
  → notice delayed 4 s (burst debounce)
  → responder: allowlisted? handled by a human? is there a newer message?
               passes the clinical gate? → AI + knowledge base
  → Meta
```

- **Never lose a message:** the webhook only acknowledges Meta once the message is queued.
- **Never reply twice:** idempotency plus a per-conversation lock with expiry.
- **Don’t reply halfway:** if the person keeps typing, the debounce waits and the responder checks there’s no newer message.
- **Clinical gate:** an explicit filter, in code, before the AI replies.
- **Suite:** HttpOnly, SameSite=Strict cookies with double-submit CSRF across sibling subdomains.

Node 20 with ESM and `node:http`, no frameworks. The main dependency is `pg`.

## Cost and availability, in writing

- **Serverless versus a single server.** The first analysis compared a single server (Lightsail), EC2, DigitalOcean, Hetzner, Azure and AWS service by service. AWS serverless won on availability, and the cost model says so plainly: it costs about USD 25 more a month than the single server (estimate, list price), almost all of it Aurora’s minimum. In exchange, there is no single server to go down, each piece scales on its own and there is no operating system to patch. To avoid lock-in, the database and the queue sit behind adapters.
- **A cost ceiling on Aurora.** A 0.5 ACU minimum with no pause, so the contact center never waits for the database to wake up, and a 2 ACU maximum as a ceiling to revisit with measured load, with an alarm when it’s reached. The test environment does pause after 10 minutes.
- **30-day retention** for conversation text, with a scheduled purge and only aggregated metrics afterwards. The MCP is read-only and aggregated, with no free-text search over transcripts. Less health data exposed, in exchange for losing historical detail.

## In production

- Live in production, serving real patients over Messenger and Instagram, with handoff to staff when needed.
- Test cases in every product, documented failure modes, a cost model, clinical-safety notes, and supply-chain and “no demo data left” verification scripts.

## What I learned

In healthcare, the hard part isn’t getting the AI to answer. It’s deciding **when it shouldn’t**, and keeping that decision in verifiable code rather than in a prompt.
