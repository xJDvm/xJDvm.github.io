## Context

The consultancy uses an internal tool to log hours against projects and tickets. The idea was to type something like *“log 3 hours on yesterday’s ticket”* in Google Chat and have it happen, without opening the tool.

The challenge wasn’t getting the model to understand the sentence. It was deciding **what we let it do** when it misunderstands.

## Architecture

- **Default-deny Cedar policy:** a single `permit` statement listing the 10 allowed actions, with no delete operation at all. When a policy denies something, the agent gets a JSON-RPC `-32002` error, not silence.
- **Idempotency in DynamoDB** (with SSE, PITR and TTL): repeating the same mutation doesn’t create two records.
- **Confirmation before mutating:** the agent proposes and the user confirms.
- **Tools as contracts:** each adapter Lambda publishes its OpenAPI 3.1 schema and the Gateway exposes it as an MCP tool.

### Decisions that changed with measurement

- **Model by configuration.** The model id isn’t in the code, because availability, latency and cost depend on the account and region. Nova Lite gave clumsy, repetitive answers; it moved to Claude Haiku 4.5, accepting two catalog reads per time listing in exchange for quality.
- **Versioned memory.** Adding preference memory meant creating a new, versioned memory instead of modifying the old one, so the migration deletes nothing.
- **Audit without content**, with encryption, point-in-time recovery and a 180-day TTL, written best-effort so it never blocks the reply.

## Verification

- **78 agent test cases** in 10 files, plus 2 gateway contract verification scripts.
- Controlled tests cover create, idempotent replay (no duplicates), 409 conflict and update.

## What I learned

A gateway with declarative policies changes the security conversation. It’s no longer about trusting the prompt. The agent simply *can’t* call what isn’t allowed. Combined with idempotency, a model mistake ends as an odd reply instead of corrupted data.
