## The problem

Respond.io is the messaging platform for the client’s B2B sales channel. Its webhooks cover messages received and sent, contacts created or updated, assignment changes, and conversations opened and closed. Every event has to reach the client’s database and often trigger something else: an after-hours alert, keyword detection, conversation analysis or a delivery update.

## The architecture

- **One topic, many queues.** SNS filters on `event_type` and each process has its own queue and Lambda. If one process fails or falls behind, the others keep going.
- **Relational persistence.** Aurora PostgreSQL 16 in a cluster inside the VPC, with its own parameter and subnet groups. Credentials live in Secrets Manager and configuration in Parameter Store.
- **Inputs that aren’t webhooks.** Files landing in S3, such as offers and quotes exported from SAP, become queue messages. A scheduled job checks pending messages every night.
- **Infrastructure as code.** The whole platform is one SAM template, with separate environments in `samconfig.toml` and a per-environment network parameter resolver.
- **Explicit ownership.** To grow without touching the main stack, I set up a *shared services* consumer stack, which for now is a scaffold. It takes the API ID and the Aurora endpoint as parameters, creates no deployments or stages, and has the VPC configuration ready for future functions.

## What I did

I was the repository’s top contributor for a year and a half, within a team. Among other things, I:

- Centralized email sending (SES) into one service.
- Set up queue-based conversation analysis.
- Built the endpoints for the delivery form and dashboard: lookups, locations and statuses.
- Moved SAP quote notes from S3 into SQS.
- Tuned the timeouts for delivery updates (up to 900 s).
- Worked on customer data.

## The same pattern in the contact center

The same client’s contact center backend follows the same architecture: 16 Lambdas and 12 queues, with SNS filters by event type. There I added audio transcription with AWS Transcribe, a satisfaction survey and email alerts for pending messages. I also set up Respond.io’s MCP server on ECS. That server is Respond.io’s open-source project: I configured and integrated it, I didn’t write it.

> Code, schemas and identifiers belong to the client. Here I describe the pattern, without data.
